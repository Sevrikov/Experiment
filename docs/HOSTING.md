# Где это может работать, и что даёт Anthropic

Записка возникла из прямого вопроса: «как перевести работу в облако на сервер
Anthropic». Ответ короткий: она **уже** там, но не в том смысле, в каком обычно
понимают «сервер».

## Что произошло в этой сессии

Работа велась в облачной сессии Claude Code — контейнер в инфраструктуре
claude.ai, не на машине пользователя. За один разговор контейнер
перезапустился **дважды**. Оба раза с диска исчезло всё:

- установленные пакеты (`numpy`, `torch`, `cadquery` — переставлялись заново)
- обученная модель и скрипты
- сводный документ со спецификацией

Уцелело ровно две категории:

1. **Опубликованные артефакты** — они хостятся на claude.ai, а не в контейнере
2. **То, что ушло в git** — а туда в тот момент не ушло ничего, репозиторий был пуст

Этот файл и весь остальной репозиторий — следствие того урока.

## Что Anthropic действительно предоставляет

| Продукт | Что исполняет | Годится под развёртывание сервиса | Тяжёлый счёт / GPU |
|---|---|---|---|
| Claude Code в облаке | агентская сессия в одноразовом контейнере | нет, контейнер изымается | нет |
| Claude API | вывод модели по запросу | нет, это не хостинг | нет |
| Claude Agent SDK | ваш агент — **на вашей** инфраструктуре | вы сами и разворачиваете | ваше железо |
| Артефакты | страница в браузере на claude.ai | только клиентский код | нет |

Отдельного продукта «вычислительные мощности Anthropic», куда можно залить
Python-сервис или поставить обучение на GPU, **не существует**. Anthropic
продаёт вывод модели, а не аренду машин.

## Что из этого следует для проекта

Проект распадается на три куска с разными требованиями, и жить они должны
в разных местах.

### Браузерная часть — остаётся на claude.ai

Три прибора из `artifacts/` целиком выполняются в браузере: типизированные
массивы, Canvas, никакого сервера. Для них артефакты claude.ai — подходящий
постоянный хостинг. Ссылки живут, страницы приватны по умолчанию и делятся
по желанию.

```
artifacts/crossbar-3d.html        схема решётки, ток по законам Ома и Кирхгофа
artifacts/crossbar-errormap.html  256x256, карта накопления ошибки
artifacts/crossbar-mnist.html     обученная сеть на аналоговой решётке
```

### Скрипты и воспроизводимость — в этом репозитории

`analog/` и `bench/` считаются за секунды-минуты на CPU. Их место — git, а
запускать можно в любой сессии после `./setup.sh`. Облачная сессия Claude Code
для этого подходит: ей не нужна персистентность, нужен только воспроизводимый
старт.

### Физика и обучение операторов — нужен настоящий GPU-хостинг

Вот чего в Anthropic нет и не будет:

- прогон FEM/SPH-решателей (часы счёта, десятки гигабайт)
- обучение нейрооператоров на данных симуляций
- долгоживущий API вокруг AI-CAD

Это задача для облака, которое продаёт машины: любой из крупных провайдеров
GPU-инстансов, либо собственный сервер. Anthropic в этой схеме — поставщик
вывода модели через API, то есть один из компонентов, а не площадка.

## Как не терять работу в облачной сессии

Проверенный в этой сессии порядок:

**Коммитить рано и часто.** Не «в конце», а как только появился осмысленный
файл. Контейнер изымается без предупреждения.

**Прописать setup script окружения.** Укажите `./setup.sh` в настройке setup
script своего окружения — зависимости будут ставиться автоматически при старте
сессии, а не вручную после каждого сброса. Полная установка (с `torch` и
`cadquery`) занимает несколько минут; `--minimal` ставит только `numpy`.

**Не держать результат только на диске.** Всё, что должно пережить сессию, —
либо в git, либо в опубликованном артефакте. Файл в `/tmp` или в рабочей папке
без коммита не существует.

**Помнить, что сетевой доступ ограничен политикой окружения.** В этой сессии
`download.pytorch.org` был закрыт прокси, а обычный PyPI и S3 с датасетом
MNIST — открыты. Если установка падает с 403 от прокси, дело в политике сети,
а не в пакете.
